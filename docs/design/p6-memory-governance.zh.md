# P6.2：短期上下文与长期记忆治理

## 目标

P6 的记忆不是“把更多历史文本塞进提示词”。短期记忆解决当前对话的连续性，长期记忆保存可追溯、可确认、可撤回的事实和偏好；两者都必须有范围、来源、版本和生命周期，不能让模型的临时推断自动变成患者事实。

## 短期记忆：事件、摘要和最近上下文

一次回答的上下文由三层组成：当前问题和最近原始对话、已经提交的结构化摘要、以及按当前问题召回的少量历史片段。最近对话优先保证指代和即时语境；摘要覆盖较早历史；历史片段只在与当前问题相关时补入。三层都有明确 token 预算，输出预留必须先扣除，超过预算时按优先级淘汰低价值片段，不能截断 JSON、剂量表或时间线。

结构化摘要至少包含：当前主诉/目标、已确认背景、尚未确认信息、已讨论建议、待追问事项、关键时间线和来源事件范围。摘要必须标记 `source_seq`、摘要版本、生成时间和策略版本。P5 的 `session_compactions` 是摘要水位和 CAS 的权威基础：新消息永远在摘要水位之后；并发摘要只能由持有前一 revision 的任务发布；失败不能覆盖旧摘要。

摘要触发由服务端策略决定，例如新事件数量、可用上下文预算、会话闲置时间或用户明确请求，不能由模型自行触发。模型摘要、OCR 或任何外部处理在调用前重新做 Capability 授权；生成的摘要先通过 JSON schema 和内容边界校验，再 CAS 发布。缓存只做加速，失效后必须从 PostgreSQL 事件和已提交摘要重建。

## 长期记忆：事实状态而非自由文本

长期记忆按类型治理：沟通偏好、稳定背景、过敏/疾病史、用药、检验趋势、医生建议、用户上传文档和系统推断候选不能混为同一种记录。每条记录至少有 tenant、用户、患者/机构范围、类型、内容或结构化值、来源证据、发生/确认/失效时间、版本、写入者和状态。

状态机为 `candidate → confirmed`，也允许进入 `conflicted`、`expired` 或 `retracted`。模型、检索或文档解析器最多创建 candidate；用户确认、具有适当权限的临床人员确认，或经过配置的可靠证据流程才能变为 confirmed。冲突记录不能被静默覆盖，而要并存并带冲突原因；撤回和过期记录保留审计历史，但默认不得用于回答。

偏好类信息可以采用较轻的确认规则，例如用户明确说明“请用简洁中文回答”即可生效；医疗事实采用更强规则，例如“对青霉素过敏”必须有用户明确确认、医疗文档证据或人工确认。一次对话中的模糊表述、低置信 OCR 或旧病历不能自动变成已确认病史。

## 写入、索引和召回

PostgreSQL 是长期记忆、状态和版本的唯一权威。先在同一事务中写入权威记录、版本历史和稳定 operation ID，再写 Outbox 意图；异步索引器才更新向量库。向量写入成功不代表事实已确认，向量删除失败也不能让已撤回记录继续在回答中可见。

召回顺序固定为：先按 tenant、用户、患者/机构授权和记忆类型过滤；再过滤非 confirmed、过期、撤回、冲突或不适用于当前时间/人群的记录；最后才根据语义相关性、来源等级、确认时间和新鲜度排序。返回给 Evidence Agent 的不是裸文本，而是带来源、状态、确认时间、不确定性和可见范围的记忆包。Safety Agent 必须检查高风险结论是否把 candidate、过期信息或不匹配人群误说成确定事实。

患者私有记忆、公共医学知识和用户偏好分域存储、分域检索。任何跨患者、跨机构或未授权的结果必须在模型读取前拒绝；不得仅依靠向量库的用户过滤作为最终权限判断。

## 交付顺序与验收

先完成短期结构化摘要的 schema、预算、CAS、恢复和上下文装配；再完成长期记忆的权威表、状态机、确认/撤回 API 与审计；然后接入 Outbox 索引、检索回查和 Evidence/Safety 证据包；最后才评估自动候选提取。新 PostgreSQL 空库是唯一来源，不迁移、双写、CDC 或回填旧 MySQL 记忆。

验收包括：摘要并发不丢新消息；缓存清空后可从事件流恢复；同一候选不能越过确认直接成为病史；撤回或过期记录即使索引尚未同步也不能被召回；冲突病史不会被覆盖；跨患者检索为零；模型失败、Outbox 重复投递或索引延迟不改变权威事实。
